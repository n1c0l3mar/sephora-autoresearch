\title{AutoResearch for Sephora Product Rating Prediction}

\maketitle

\begin{abstract}
This project studies whether structured Sephora product metadata can predict product ratings. I used an AutoResearch loop in which an agent modified only the model definition, ran a fixed evaluator, and retained changes only when validation mean absolute error (MAE) improved. The linear regression baseline achieved a validation MAE of 0.3825. Random Forest modeling reduced MAE to 0.3284, while repeated model-only tuning showed diminishing returns. The best result, 0.3225, came from the improved feature representation that included \texttt{brand\_name} as a categorical predictor. The final result supports a modest conclusion: for this dataset, meaningful feature representation mattered more than an extended hyperparameter sweep.
\end{abstract}

\section{Introduction}

The research question is: how well can Sephora product ratings be predicted using structured product metadata? Product ratings are influenced by many factors that are difficult to observe directly, but product-level fields such as price, category, availability, and brand may still contain useful signal. The goal of this project is not to claim a complete explanation of customer ratings. Instead, it is to build a reproducible experimental trace that compares modeling directions under a fixed evaluation procedure.

The project used an AutoResearch workflow. An agent could change the model implementation while the evaluator, data split, target, and metric remained fixed. This design made it possible to compare simple linear models, ensemble models, Random Forest hyperparameters, and a later feature-representation improvement. The strongest result was a feature-engineered Random Forest with validation MAE 0.3225, compared with 0.3825 for the baseline linear regression.

\section{Dataset and Evaluation}

The project uses \texttt{product\_info.csv} from the Sephora products and skincare reviews dataset. The target variable is \texttt{rating}. Rows with missing target values are removed before splitting. The repository defines a deterministic 70\% train, 15\% validation, and 15\% test split with \texttt{random\_state = 390}. The final test set was not used during model search.

The comparison metric is validation mean absolute error (MAE), where lower values are better. Numeric predictors are median-imputed. Categorical predictors are imputed with their most frequent value and one-hot encoded with unknown categories ignored. The final direction keeps \texttt{brand\_name} as a categorical predictor. The repository also contains a feature-engineering module for structured product signals, but the central recorded improvement in the experiment log is the addition of \texttt{brand\_name}.

\section{AutoResearch Loop Design}

The experimental protocol restricted edits to \texttt{model.py}. The files \texttt{prepare.py}, \texttt{run.py}, and \texttt{product\_info.csv} were frozen, and \texttt{results.tsv} could not be edited manually. Each experiment followed the same loop:

\begin{enumerate}
    \item Modify the model or its hyperparameters in \texttt{model.py}.
    \item Run \texttt{python3 run.py "<description>"}.
    \item Fit on the training split and compute validation MAE.
    \item Append the description, MAE, runtime, status, decision, and any error message to \texttt{results.tsv}.
    \item Keep the new model only if its MAE is lower than the previous best; otherwise discard it and restore the best working model. A run without a valid MAE is recorded as a crash.
\end{enumerate}

This narrow editable surface reduced the risk of changing the split or metric while searching. It also preserved unsuccessful experiments, making the archive useful for diagnosing plateaus rather than reporting only favorable runs.

\section{Experimental Results}

Table~\ref{tab:results} summarizes the most important experiments from \texttt{results.tsv}. The linear models produced only small improvements over baseline. Random Forest created the largest model-family improvement: 100 trees reduced MAE from 0.3825 to 0.3311. Increasing to 300 and then 400 trees with \texttt{max\_features=0.7} improved MAE to 0.3289 and 0.3284. Extra Trees and Gradient Boosting did not beat this setting.

The controlled Random Forest sweeps clarified the plateau. Changing \texttt{max\_features} generally stayed around 0.329--0.330 and did not improve on 0.3284. Increasing \texttt{min\_samples\_leaf} from 1 to 5, 10, 25, and 50 worsened MAE from 0.3284 to 0.3347, 0.3380, 0.3448, and 0.3520. A 1000-tree run achieved 0.3289, adding runtime without improving validation error. In the later autonomous block, depth limits, bootstrap subsampling, Extra Trees, and Gradient Boosting also failed to beat the best Random Forest.

The most important change was feature representation. Adding \texttt{brand\_name} as a categorical predictor improved MAE from 0.3284 to 0.3225. A post-feature-engineering tuning block then tested nearby Random Forest and Extra Trees settings. Its closest result was 0.3226 from a 600-tree Random Forest, which did not beat the retained model. The final model therefore remains the Random Forest direction with the improved feature set.

\section{Failure Analysis and Reflection}

Random Forest consistently outperformed the linear models because the relationship between structured product metadata and ratings appears to be nonlinear and interaction-dependent. The linear regression baseline achieved MAE 0.3825, Ridge Regression achieved 0.3821, and Lasso Regression achieved 0.3806. These small changes suggest that regularizing a linear decision surface did not address the main modeling limitation. In contrast, a 100-tree Random Forest reduced MAE sharply to 0.3311. A tree ensemble can represent threshold effects and interactions without specifying them in advance. For example, the predictive value of price may depend on product category, sale status, variation count, or brand. The experiment log does not identify a single causal interaction, but the size of the Random Forest improvement is consistent with a problem where flexible partitions are more useful than global linear coefficients.

Repeated hyperparameter tuning then produced diminishing returns. Moving from 100 trees to 300 trees improved MAE from 0.3311 to 0.3289, and a 400-tree forest with \texttt{max\_features=0.7} reached 0.3284. Beyond that point, nearby changes mostly moved sideways or backward. A 500-tree forest scored 0.3286, a 1000-tree forest scored 0.3289, and controlled \texttt{max\_features} settings generally stayed near 0.329--0.330. Increasing \texttt{min\_samples\_leaf} was clearly harmful: MAE worsened from 0.3284 at leaf size 1 to 0.3347, 0.3380, 0.3448, and 0.3520 at leaf sizes 5, 10, 25, and 50. Depth caps and bootstrap subsampling also failed to improve the retained model. These experiments suggest that the forest had already captured most of the signal available from the original representation. More tuning could change variance and runtime, but it did not create new information.

The contrast between model improvements and feature improvements was the central lesson of the logs. Model-family selection mattered greatly at first: replacing linear regression with Random Forest reduced MAE by more than 0.05. However, later model-only searches plateaued around 0.3284. Adding \texttt{brand\_name} as a categorical predictor then reduced MAE to 0.3225, a larger improvement than any late-stage hyperparameter adjustment. The post-feature-engineering tuning block reinforced this interpretation. Its closest result was a 600-tree Random Forest at 0.3226, while nearby \texttt{max\_features} settings and an Extra Trees variant were worse. The most productive late-stage change was therefore not a more elaborate estimator, but a representation change that exposed meaningful product metadata to the existing model.

The archive also records two crashes. These were not intentional tests. One run produced \texttt{ValueError: too many values to unpack (expected 5)}, revealing a mismatch at the data-loader or evaluator interface. Another passed an invalid \texttt{n\_estimators} value to Random Forest and produced an \texttt{InvalidParameterError}. Both failures were logged with no MAE and classified as crashes. The logs do not contain a separate observed import-error run, but wrong imports remain a realistic risk because \texttt{run.py} imports \texttt{build\_model()} directly from \texttt{model.py}. Candidate estimators also had to remain compatible with the fixed preprocessing output. In addition, runtime behavior was not always predictable: one successful Random Forest probe was logged at 6814.4588 seconds, while many comparable runs completed in tens or hundreds of seconds.

The AutoResearch loop worked well in several respects. It enforced a single validation metric, retained unsuccessful runs in \texttt{results.tsv}, and made keep, discard, and crash decisions explicit. The fixed split and fixed MAE metric prevented evaluation drift: an apparent improvement could not be created by quietly changing the validation rows, target, or scoring function. Rolling back discarded models preserved a valid working state and made each experiment interpretable relative to the current best. This discipline was especially important once gains became small, because differences such as 0.3225 versus 0.3226 should be evaluated under exactly the same protocol.

Preventing evaluation drift also required resisting seemingly convenient changes during debugging. The evaluator loaded the deterministic split from \texttt{prepare.py}, computed validation MAE in \texttt{run.py}, and appended every result to the same archive. The final test set remained unused during search. Without those constraints, repeated experiments could accidentally optimize against a moving target or leak test information into model selection. In future work, I would add automated checksums or configuration snapshots for the split, target, metric, and frozen files so that each logged row carries evidence that it was evaluated under the same contract.

The loop was weaker at allocating search effort. It spent too many runs exploring narrow Random Forest neighborhoods after the plateau was already visible. It also launched expensive fits before checking parameter validity, interface compatibility, or likely runtime. Human judgment was required to stop broad model exploration, interpret the feature-representation improvement, and lock the final direction. A future version should use staged execution: first run import and pipeline-construction checks, then fit on a small smoke-test subset, and only then perform full validation. It should enforce a runtime budget, record the parent model for each experiment, and stop a search axis after several non-improvements. Finally, the editable boundary should remain narrow and versioned. Keeping the metric, split, and evaluator fixed is not merely a reproducibility convenience; it is the condition that makes autonomous comparisons credible.

\section{Conclusion}

This project used a constrained AutoResearch loop to predict Sephora product ratings from structured metadata. The baseline linear regression achieved validation MAE 0.3825. Random Forest modeling produced a large improvement to 0.3284, but additional model-only tuning plateaued. The best recorded result was 0.3225 after including \texttt{brand\_name} as a categorical predictor in the improved feature representation. The main lesson is not that one hyperparameter setting is universally optimal, but that a fixed, auditable evaluation loop can distinguish productive modeling changes from costly tuning with diminishing returns.
